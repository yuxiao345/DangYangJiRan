⚠️ **两个必须避免的动作：**

1. **不要打开嫌疑设备上的钱伲。** 一打开就会先把服务器上的坏数据导入，把它本地快照覆盖掉

2. **不要"关闭该 App 的 iCloud 开关" / 不要退出 iCloud。** Apple DTS 明确：这属于**设计行为**
   （隐私原因，无 API 可关），会**抹掉该设备上的本地 store**。

**正确做法：保持离线**（飞行模式 / 关机），什么都不做。

**安全的核查办法（确实需要确认某台设备是否落后时）**：**先开飞行模式**，再打开钱伲看账户名字是新的还是旧的，
看完**强制退出**，然后**在恢复网络之前**删掉 App。

**删除对云端是安全的**（已查证）：删一台设备上的 App 不会删云端数据。
Mac 还在 ⇒ 安全。⚠️ **修复期间不要把所有设备上的钱伲都删掉。**

## 取证方法备忘（可复用）

- 库位置（Mac）：`~/Library/Containers/com.qianey.app.mac.Qianeymac/Data/Library/Application Support/FirstCC.sqlite`（+ `-wal`/`-shm`）
- 只读打开：`NSReadOnlyPersistentStoreOption: true`，配合 `NSPersistentHistoryTrackingKey: true`
- 字段级判定靠 `NSPersistentHistoryChange.updatedProperties`（只列真正变过的属性，不存旧值/新值）
- 作者区分：`NSPersistentHistoryTransaction.author` 以 `NSCloudKitMirroringDelegate` 开头 = 从别的设备导入；否则 = 本机写入
- 同步事件表 `ANSCKEVENT`：`ZCLOUDKITEVENTTYPE`（0=setup / 1=import / 2=export）、`ZSUCCEEDED`、`ZERRORCODE`、`ZERRORDOMAIN`；
  **⚠️ `ZCOUNTAFFECTEDOBJECTS` / `ZCOUNTFINISHEDOBJECTS` 恒为 0，不可用于量化规模**
- 镜像元数据表（解释"为何全量重传"）：`ANSCKRECORDMETADATA`（`ZLASTEXPORTEDTRANSACTIONNUMBER` / `ZNEEDSUPLOAD` /
  `ZCKRECORDNAME` / `ZSYSTEMFIELDSASSET`）、`ANSCKEXPORTEDOBJECT`、`ANSCKHISTORYANALYZERSTATE`、
  `ANSCKRECORDZONEMETADATA`（`ZNEEDSRECOVERYFROMIDENTITYLOSS` / `ZCURRENTCHANGETOKEN`）
- 子类必须用 `A` 前缀（`ACHANGE` / `ATRANSACTION`），不是 `Z` 前缀
- 实体编号：`Z_PRIMARYKEY`（1=Account, 3=BudgetItem, 7=Ledger, 11=RecurringRule, 14=Transaction, 15=TransactionTemplate）
- 模型：`xcrun momc FirstCC.xcdatamodeld -o /tmp/momout/FirstCC.momd`
- **行布局（实测解码成功，可用于任意表）**：SQLite 标准 record —— 头部 = 1 字节头长 + 每列一个 serial type；
  `Z_PK` 恒为 serial 0（`INTEGER PRIMARY KEY` 即 rowid，记录里存 NULL）。字段顺序与 `.schema` 的建表顺序**完全一致**。
  实测 BudgetItem #9 记录 49 字节：`0b | 00 01 01 03 09 01 02 07 19 2c | 03 | 65 | 2d c6 c0 | (09=常数1零字节) | 02 | 02 4b | 3fe999999999999a(0.8) | 每年 | <16B UUID>`
  ⇒ 整数按位数选 serial（3=int24 如 `2d c6 c0`=3,000,000），浮点 `07`=float64，文本/`ZID` 变长。
  **定位任意行**：拿该行 `ZID` 的 16 字节去文件里搜偏移，再按上面的顺序往前/后读。

### 净资产复算（2026-10-08 实测通过，5 分钟可复现）

- **App 口径**：`DashboardViewModel.totalBalance = Σ AccountServiceImpl.calculateBalance(for:)`，
  **含归档账户**，范围为**当前账本**（取 App 偏好里的 `currentLedgerID`）。
- `balance = 期初 + Σ(该账户 isReconciled == NO && parentTransaction == nil 的金额)`；
  金额取法 `ledgerAmount = convertedAmount ?? amount`，且
  `useLedgerAmount = (账户币种 == 账本币种)`：相等用 `ledgerAmount`，**不相等用原币 `amount`（不换算）**。
- 借贷账户（`typeRaw == "借贷"`）走两轮特例：第一轮 `borrowIn + 待结算` 计 `-(amt - min(settled, |amt|))`，
  其余方向跳过；第二轮取 `toAccount == 本账户 && typeRaw == "借贷"`（`lendOut+待结算` 计 `-(amt + min(settled, |amt|))`；
  非借贷账户的 `collect/borrowIn` 计 `+amt`）。
- **汇率不进这个数（实测，别再拿汇率差解释差额）**：`ZEXCHANGERATE` **表是空的**；
  全库 **0 笔** `ZCONVERTEDAMOUNTINFEN != 0`；外币账户币种都设对了（EUR/THB/MYR/HKD/SGD/USD）
  ⇒ 走"原币"分支。**净资产 = 各币种原值直接相加**（500 欧元就是按 500 计入）。
- **复算工具**：`/tmp/bal/`（编译 App 真实源码，不手抄逻辑）
  ```
  swiftc -O -o /tmp/bal/bal /tmp/bal/main.swift @/tmp/bal/files.txt
  ```
  `files.txt` = `Models/CoreData/*.swift`（**排除** `AccountAllocationItem+Aggregate.swift`，它依赖 SwiftUI）
  + `Models/Enums/*.swift` + `Extensions/Decimal+Currency.swift`
  + `Services/Protocols/AccountServiceProtocol.swift` + `Services/Implementations/AccountServiceImpl.swift`
  （`AccountServiceImpl` 只依赖 Foundation + CoreData，所以能脱离 App 单独编译）。
- **实测结果：复算 = 4,360,948.35，与 App 显示一字不差**（基准 4,361,030.27 − 81.92）。
